# Public live-data fusion source notes

## Candidate use case: Natural-hazard situational intelligence

DataForge will fuse independent public feeds into a **local, evidence-backed hazard-operating picture**. The use case is deliberately not an alerting authority or emergency-dispatch system: it detects data-quality and reconciliation risks, correlates only when the evidence is explicit, and requires human approval before any external action.

| Publisher                                                                          | Intended feed                             | Verified operating property                                                                                                                                                                                               | Adapter implication                                                                                                                                                                                         |
| ---------------------------------------------------------------------------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [USGS](https://earthquake.usgs.gov/earthquakes/feed/v1.0/geojson.php)              | Real-time earthquake GeoJSON summary feed | USGS describes the feed as a programmatic GeoJSON interface; the hour/day/week/month summaries are updated every minute and expose event IDs, origin/update time, magnitude, location, network, status, and geometry.     | Use immutable source ID plus `updated` timestamp for revision detection; fetch on a bounded cadence, record source URL and observation time, and do not infer a missing earthquake from a different source. |
| [National Weather Service](https://www.weather.gov/documentation/services-web-API) | Public alerts and observations API        | NWS documents alerts, observations, forecasts and related weather data. The API is cache-oriented, requires a User-Agent, and has unpublished but reasonable rate limits; it advises retry after rate-limit errors clear. | Use conditional/cached fetches, bounded exponential retry, a configured User-Agent without private data, and a source-health event for rate-limit or response failure.                                      |
| [NASA EONET](https://eonet.gsfc.nasa.gov/)                                         | Curated open natural-event metadata       | NASA identifies EONET v3 as the current stable API and describes it as a curated, continuously updated near-real-time reference for natural-event metadata, including linked event sources and geometry.                  | Treat EONET as a contextual catalog, not ground truth for an unrelated USGS/NWS event. Preserve category, source link, geometry timestamp, magnitude value and magnitude unit.                              |

## Live endpoint verification

On the implementation date, all selected endpoints returned usable public JSON: the USGS past-hour feed contained seven earthquake features; the NWS active-alert endpoint returned a large GeoJSON collection; and EONET returned active event metadata with category, source and geometry histories. These observations establish connector viability only. The implementation records collection time and response shape because event count and content are expected to vary over time.

The source contracts, real-time test harness, and local replays will store only public feed payloads and test fixtures. They do not receive user datasets or send user data to any source.
